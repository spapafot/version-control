# VersionControl.gr

Free interactive Git course — "Learn Git, using Git".
Fully static Next.js app (no backend): a real Git engine runs in the browser.

## Commands

- `pnpm dev` — dev server
- `pnpm test` — Vitest: engine, shell, validators + **every challenge solvable via its solution script**
- `pnpm build` — static export to `out/` (must stay `output: 'export'` compatible)
- `pnpm smoke` — real-browser E2E via puppeteer-core + Edge (needs `node scripts/serve-out.mjs` running; `BASE=` overrides target)
- **Deploys live in `deploy/`** (bash, Git Bash on this machine), each also exposed as a pnpm script: `deploy_frontend.sh` (`pnpm run deploy`) = build + `wrangler deploy` — ships the static site AND the `/verify/*` edge worker, since root `wrangler.jsonc` bundles `worker/index.ts`; `deploy_worker.sh` (`deploy:worker`) = the API proxy (`workers/api` → api.versioncontrol.gr, `keep_vars` preserves dashboard vars); `deploy_backend.sh` (`deploy:backend`) = vc-api Lambda code via `scripts/aws/60-update-lambda.sh` (env vars untouched); `deploy_quiz.sh` (`deploy:quiz`) = reseed the vc-quiz bank; `deploy_all.sh` (`deploy:all`) = all of it, backend FIRST — the Lambda whitelists slugs, so shipping the frontend first silently drops synced progress on new missions. NOTE: must be `pnpm run deploy`, plain `pnpm deploy` is a reserved pnpm command.
- `pnpm seo:check` — validates the built `out/` (canonicals, one h1 per page, og:image, JSON-LD parses, sitemap covers every indexable page, **body text is not empty**). Run after `pnpm build`.
- `pnpm seo:keywords` — regenerates `docs/seo/keyword-map.md` from `src/challenges/seo.ts` + `src/lib/page-seo.ts`.
- `cd backend && python -m pytest` — FastAPI/DynamoDB suite under moto (needs `requirements-dev.txt`).
- `python backend/tools/seed_quiz.py --validate-only` — check `src/quiz/bank/*.json` with no AWS calls; `--dry-run` adds the diff against the table; neither flag writes.
- `python backend/tools/seed_leaderboard.py --dry-run` — print the demo leaderboard rows; without the flag it writes them, `--purge` deletes them again (see the gotcha below).

## Architecture

- `src/git/` — GitEngine: isomorphic-git on a memfs Volume. Gap commands implemented on primitives: reset/revert/restore/switch/cherry-pick/stash (`ops/`). Merge conflicts via `abortOnConflict:false` + our own MERGE_HEAD state. `state.ts#buildRepoState` is THE snapshot read after every command (feeds graph, panels, validators). `ops/remote.ts`: simulated origin — a second GitEngine at `/origin` on the SAME volume (`engine.remote`, attached by the `publish` setup step); fetch/push copy objects deflated between the two object stores (byte-identical ⇒ stable oids); pull = fetch + the normal merge machinery.
- `src/terminal/` — tokenizer (quotes, `>` redirection), CommandSpec parser, shell dispatch, xterm-agnostic readline (history/tab-complete; its `prompt` may be a function, re-read on every draw, which is how `format/prompt.ts` puts the live branch in front of the `$` — `(feature/footer) $` — the way Git Bash does), `commands/git/*` print **verbatim real-git English output**, coloured through `ctx.paint` (`format/color.ts`) with git's own `color.*` defaults: status staged green / unstaged, untracked, unmerged red; diff meta bold, `@@` cyan, `+` green, `-` red; `git branch` current green; log decorations HEAD cyan, branches green, remote-tracking red, hash and brackets yellow.
- `src/validators/` — pure predicates over RepoState; challenges pass on final state, never on exact commands.
- `src/challenges/` — 74 challenges in 11 sections; declarative `setup` steps run under a deterministic clock (stable hashes across resets); `solution` used only by the test harness.
- `src/lib/game-store.ts` — Zustand session store (engine/shell/snapshot/evaluation); `progress.ts` — persisted progress/achievements/settings.
- **Quiz** (`/quiz/`) — timed multiple-choice, **scored server-side**. `src/quiz/bank/*.json` (one file per section, gitignored like `src/challenges`) is the authoring source of truth; `backend/tools/seed_quiz.py` validates it and loads it into the **`vc-quiz`** DynamoDB table (PK/SK + TTL on `ttl`, no GSIs). `backend/app/quiz.py` is the pure draw/score/rank logic, `quiz_db.py` the table access plus an in-memory bank cache, `routes/quiz.py` the four endpoints. Frontend: `src/lib/quiz-api.ts` (types + wrappers), `quiz-store.ts` (session, not persisted), `quiz-local.ts` (device bests, key `versioncontrol-quiz`), `src/components/quiz/*`.
- SEO: `src/lib/seo.ts` (`pageMetadata()` builds title/description/canonical/OG/Twitter — every page goes through it, so nothing drifts), `src/lib/schema.ts` (JSON-LD builders cross-referenced by `@id`), `src/lib/page-seo.ts` (top-level page copy), `src/challenges/seo.ts` (per-mission keyword titles, **parallel to** the in-game titles, which stay as they are). `src/app/opengraph-image.tsx` generates the 1200x630 card at build; it needs `dynamic = "force-static"` like the other metadata routes.
- UI: retro CRT arcade design system in `globals.css` + `components/ui/pixel.tsx`. Fonts: Inter Variable (titles), IBM Plex Sans (body), JetBrains Mono (terminal).

## Gotchas

- **`ssr:false` routes must keep a server-rendered counterpart.** `/challenge/*` and `/playground/` load their screens via `next/dynamic` `ssr:false`, so on their own they prerender an empty `<body>` and are unrankable. `MissionBrief` (challenge) and `PlaygroundAbout` are server components rendered as siblings of the client boundary to supply real HTML; they own the page's single `<h1>`, which is why `MissionPanel` renders an `<h2>`. `pnpm seo:check` fails if any page's body text drops below 250 chars, so do not "fix" that by deleting the section.
- **Those counterparts are prose in a dialog, not a section under the game.** Both render inside `NotesDialog` (`src/components/challenge/NotesDialog.tsx`), which keeps them in the HTML under `hidden` until the "Lesson notes" / "About" button opens them, so the game itself fits one viewport with no page scroll. `hidden` still counts for `seo-check.mjs` (it reads text, not layout) — rendering them conditionally instead would empty the body and fail the build's SEO pass. The button and the dialog never share a React parent (one is inside the `ssr:false` screen, the other beside it), which is what `src/lib/notes-dialog.ts` exists for. `pnpm smoke` asserts the page does not scroll at 1440x900 and that the dialog opens and closes on Esc.
- **`/quiz/` is the deliberate exception.** Its About sibling was removed on request, so it prerenders an empty body with no `<h1>` and will not rank. `seo-check.mjs` carries a `bodyless` allowlist holding exactly that one path, and `sitemap.ts` still lists the URL. Adding a second entry to that allowlist is almost certainly wrong: an empty body normally means someone added an `ssr:false` boundary and forgot the sibling.
- **A page that exports its own `openGraph` stops inheriting the file-convention OG image.** Next silently drops it, which left 68 of 69 pages with no card. `pageMetadata()` sets `images: [OG_IMAGE]` explicitly; any new page must go through it. The generated image lands in `out/` with no file extension, so `public/_headers` supplies its `Content-Type` (verified: `wrangler dev` serves it as `image/png`).
- **The completion card is not a modal, and must not become one.** `SuccessOverlay` is a corner card (`role="status"`, no backdrop, no focus steal, terminal stays live) anchored to the top-right of the game grid, which is why that grid is `relative`. A mission is usually finished by a command whose *output* is the lesson — "your branch is up to date with 'origin/main'" — and the old centred dialog covered it the instant it was earned. `pnpm smoke` asserts the card's rect never intersects the terminal's.
- **Terminal colour dies at a redirect.** `ctx.paint` is `painter(!redirect)` (`shell.ts`), mirroring git's isatty rule: `git status > report.txt` has to write plain text, or the escape codes end up in the file and the learner sees them in `cat`. Any new coloured output must go through `ctx.paint`, never a bare `\x1b[…m`. Use the basic 30-37 codes, which `TerminalPanel`'s theme maps onto the CRT palette; truecolor escapes bypass it. `shell.test.ts` decolours `out`/`err` in its `run()` helper and keeps `raw` for the colour assertions, so wording tests stay about wording.
- **Racy index**: memfs same-size writes within 1 ms are invisible to `statusMatrix` stat-checking. `engine.writeFile` bumps a monotonic mtime — always create files through the engine, never raw fs writes. This applies to `/origin` too: never raw-fs-write into the origin repo.
- **Simulated origin invariants**: the origin engine gets its OWN `cache` object (never share caches across repos) but shares the FsProvider/volume. `onRemote` setup steps share the main setup's clock closure — never give origin its own counter, or reset determinism breaks. Origin is logically bare after setup: learner pushes move `refs/heads/*` only, its worktree/index go stale by design, and nothing may read them post-setup. `buildRepoState` walks TRACKING oids only, never origin's actual tips (their objects may not exist locally before a fetch).
- **The quiz answer must never reach the browser before a submit.** Bank options are stored with the correct answer FIRST (`options[0]`); `quiz.draw` shuffles per session and records the permutation on the session item, so `QuizStartOut` carries neither `correct` nor `explanation`. `test_quiz_api.py` asserts the response key set structurally — if you add a field to that model, check it there too.
- **A quiz session is single use and its clock is the server's.** `claim_session` stamps `submittedAt` with a conditional write, and elapsed time is computed from the stored `startedAtMs`, never from the client. Ranking additionally needs a signed-in owner, a `nickname` on the profile, submission inside the deadline plus grace, and a run longer than `MIN_RUN_MS`; failing any of those still returns the score, with `ranked: false` and a reason.
- **Do not reintroduce a per-answer pace floor.** There was one (`elapsed >= answered × 900ms`) and it silently discarded better runs: sprint scores exactly how fast you answer, so the check fought the mode it was policing, and it got worse as players recognised repeats. `MIN_RUN_MS` bounds the whole run instead, purely so a scripted instant submit cannot park a `0:00` atop the Set of 20 board. `test_a_better_and_faster_sprint_takes_the_board` pins this; its 12s/15-answer numbers sit inside the old floor on purpose, so loosening them makes it pass against the bug it exists for.
- **Two names per profile, and they are not interchangeable.** `displayName` is printed on the certificate and is usually a real name; `nickname` is what the public boards show. `PUT /v1/me` takes either or both and leaves the other alone. Ranking reads `nickname` only, so a player with just a certificate name gets `no_nickname`.
- **A sprint's `total` is the pool dealt, not a target.** `SPRINT_POOL` (150, clamped to bank size) is deliberately unreachable, so the UI shows no denominator, no progress bar and no question dot grid for sprint, and the sprint board hides Time because every run lasts the full three minutes.
- **Some rows on the live boards are demo rows.** `backend/tools/seed_leaderboard.py` writes a top ten per board so a new board is not empty; every one has a `sub` starting `demo-`, which is the only marker (the API never returns `sub`). Their scores are deliberately beatable — a board a learner cannot climb is worse than an empty one — so keep any edit to `SET20_RESULTS`/`SPRINT_SCORES` on the ordinary side. They own no `USER#{sub}/BEST#…` pointer and no profile, so nothing else in the system can touch them, and re-running the tool purges its own rows before rewriting — never hand-edit a board row instead. When counting real players, filter that prefix out.
- **One leaderboard row per player per board** is an invariant, not a coincidence: `USER#{sub}/BEST#{mode}#{period}` names the live row, and `record_best` advances the pointer, writes the new row and deletes the old one in a single `TransactWriteItems`. Reading a board is therefore a plain ascending Query with no dedup. `dynamodb:DeleteItem` exists on the role for exactly this.
- **A new Lambda env var will not appear from a deploy.** `QUIZ_TABLE_NAME` has to be set by hand in the console; `60-update-lambda.sh` deliberately never touches the environment. Same for re-running `30-create-iam-role.sh` after adding a table.
- **Re-seeding the bank needs no redeploy**, but takes up to `BANK_RECHECK_SECONDS` (5 min) to reach warm containers: `quiz_db.get_bank()` only re-Queries when `QBANK#META/VERSION.rev` changes, and the seeder bumps that rev last so a half-written bank is never picked up.
- Only `/v1/quiz/leaderboard` is edge-cached (`CACHEABLE_PATH` in `workers/api/src/index.ts`); session and submit routes match nothing and must stay that way.
- isomorphic-git cache object must be recreated together with a new Volume (see `reset` in game-store).
- **Do not swap `ops/stash.ts` for isomorphic-git's native `git.stash`**: it restores files with raw fs writes (racy index — a same-size restore goes invisible), stamps `new Date()` into its intermediate commit messages (setup stashes stop being reproducible), and takes no `cache`. Stash entries live in memory on the engine, like `reflog`.
- All `next/link` uses `prefetch={false}`: Next 16 segment-prefetch `.txt` URLs 404 on static hosting.
- HUD/label text uses CSS `text-transform: uppercase` — browser `innerText` assertions must match the UPPERCASE text.
- xterm/isomorphic-git/memfs stay behind `next/dynamic` `ssr:false` boundaries (`ChallengeClient`, `PlaygroundClient`).
